This document provides a deep, serial-wise walkthrough of every code file in the FinishIt repository. It is designed to transform a "vibe-coded" understanding into senior-level technical ownership.

--------------------------------------------------------------------
MENTAL MODEL: THE LAYERS OF FINISHIT
--------------------------------------------------------------------
FinishIt is a "Thick Client" Single Page Application (SPA).
1. UI LAYER (JSX): React components (pages/components) render the view.
2. STATE LAYER (Context): Global states like Auth and Notifications.
3. LOGIC LAYER (Services): Data fetching, normalization, and algorithms (Eisenhower Matrix, Streaks).
4. DATABASE LAYER (PostgreSQL): Data persistence with strict relational integrity.

==================================================
FILE 1: frontend/package.json
==================================================
1. File Purpose: The project's manifest. Defines dependencies, scripts, and metadata.
2. Theory: Node.js ecosystem uses this to manage libraries. "dependencies" are needed for production; "devDependencies" only for building/linting.
3. Code Walkthrough:
   - "type": "module" -> Enables modern ES Modules (import/export).
   - "dependencies": Includes @supabase/supabase-js (DB), react (UI), react-router-dom (URLs).
   - "scripts": "dev" starts Vite; "build" creates a production-ready bundle.
4. Connection: Controls every other frontend file by managing their imports.
5. Interview: "What's the difference between package.json and package-lock.json?" (A: Lock file ensures exact versions across all environments).

FILE 2: frontend/vite.config.js

SECTION: PROJECT-WIDE INTERCONNECTIONS
--------------------------------------------------------------------

1. DATA FLOW (The Lifecycle of an Action)
   - User clicks "Complete Task" in TaskManagementPage.jsx.
   - Page calls tasksApi.updateTask().
   - tasksApi calls Supabase.
   - Postgres Trigger set_updated_at() runs.
   - tasksApi calls recordTaskHistory().
   - UI updates local state 'tasks'.
   - React detects state change, re-renders TaskCard.
   - (After 60s) NotificationProvider polls and detects the task is gone from "Pending", removing its alert.

2. AUTHENTICATION FLOW
   - Supabase Auth manages JWT.
   - AuthProvider stores session in state.
   - ProtectedRoute intercepts URL changes, checking state.
   - Services get JWT from supabase.auth automatically.

3. ARCHITECTURE DIAGRAM (Text-based)
   [USER INTERFACE] 
      ↑ (State Updates)
   [CONTEXT PROVIDERS (Auth, Notif)]
      ↑ (Data snapshots)
   [SERVICES LAYER (API, Algorithms)]
      ↑ (JSON / Auth Header)
   [SUPABASE / EXTERNAL APIs (Groq, Google)]
      ↑ (SQL Queries)
   [POSTGRESQL DB]

--------------------------------------------------------------------
SECTION: CODEBASE ARCHITECTURE MAP
--------------------------------------------------------------------

1. FOLDER RELATIONSHIPS
   - src/providers: Logic wrappers for the whole app.
   - src/services: The "Engine room". Pure functions, zero JSX.
   - src/pages: The "Directors". They tell services to get data and tell components to show it.
   - src/components: The "Actors". Reusable, dumb UI blocks.

2. LAYERED DESIGN
   - Separation of Concerns: You can swap the CSS Feature files without touching the API files.
   - Single Source of Truth: All data flows from the Database -> Snapshot Service -> Page State.
